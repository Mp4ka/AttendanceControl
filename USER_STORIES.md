## US-01. Навигация по разделам

**История.** Как преподаватель, я хочу с главного экрана перейти в нужный раздел
(«Студенты», «Отметить посещаемость», «Статистика»), чтобы не искать функции по всему приложению.

**Приоритет:** Must. **Спринт:** 1. **Статус:** ✅ выполнено.

**Критерии приёмки:**

- [x] После запуска приложения открывается главный экран с названием приложения.
- [x] На экране видны три кнопки-раздела: «Студенты», «Отметить посещаемость», «Статистика».
- [x] Нажатие на «Студенты» открывает экран `StudentsActivity` с заголовком «Студенты».
- [x] Нажатие на «Отметить посещаемость» открывает экран `AttendanceActivity`.
- [x] Нажатие на «Статистика» открывает экран `StatisticsActivity`.
- [x] Кнопка «Назад» на любом экране раздела возвращает в главное меню.

**Сценарий проверки (GWT):**

- **Дано** приложение запущено и открыт главный экран,
- **Когда** преподаватель нажимает «Студенты»,
- **Тогда** открывается экран раздела «Студенты», а по нажатию «Назад» снова виден главный экран.

**Тест-кейсы:** TC-01, TC-02, TC-03.

## US-02. Просмотр списка студентов

**История.** Как преподаватель, я хочу видеть список студентов выбранной группы,
чтобы быстро отметить посещаемость и проверить состав.

**Приоритет:** Must. **Спринт:** 2. **Статус:** ✅ выполнено.

**Критерии приёмки:**

- [x] На экране «Студенты» отображается список карточек: инициалы, фамилия и имя, группа.
- [x] Список отсортирован по фамилии, затем по имени.
- [x] В заголовке экрана виден счётчик «Студентов: N».
- [x] Если студентов нет, выводится сообщение «Пока нет студентов» и кнопка «Добавить студента».
- [x] Список обновляется сразу после добавления или удаления записи без перезапуска.

**Тест-кейсы:** TC-05, TC-10.

## US-03. Добавление студента с проверкой полей

**История.** Как преподаватель, я хочу добавить студента, указав фамилию, имя и группу,
чтобы включить его в список для отметки посещаемости.

**Приоритет:** Must. **Спринт:** 2. **Статус:** ✅ выполнено.

**Критерии приёмки:**

- [x] Форма содержит поля «Фамилия», «Имя», «Группа» и кнопку «Сохранить».
- [x] Пустое поле подсвечивается ошибкой «Заполните поле», форма не закрывается.
- [x] Строка из одних пробелов отклоняется с ошибкой «Поле не может состоять из пробелов».
- [x] Значение длиннее 40 символов отклоняется с ошибкой «Слишком длинное значение (не более 40 символов)».
- [x] После успешного сохранения форма закрывается, студент появляется в списке, показывается «Студент добавлен».
- [x] Повторное добавление того же студента в ту же группу отклоняется с ошибкой
      «Такой студент уже есть в этой группе»; другой группе — разрешено.

Правила ввода и точные тексты — в [docs/STUDENT_INPUT_SPEC.md](docs/STUDENT_INPUT_SPEC.md).

**Тест-кейсы:** TC-06, TC-07, TC-08, TC-09, TC-11.

## US-04. Удаление студента с подтверждением

**История.** Как преподаватель, я хочу удалять студента из списка, чтобы не хранить устаревшие записи
и не отмечать отсутствующих в группе людей.

**Приоритет:** Should. **Спринт:** 2. **Статус:** ✅ выполнено.

**Критерии приёмки:**

- [x] Удаление запускается кнопкой-корзиной на карточке или долгим нажатием на карточку.
- [x] Перед удалением показывается диалог «Удалить студента?» с текстом
      «Удалить <Фамилия Имя> из списка? Отметки посещаемости этого студента тоже будут удалены.»
- [x] При отказе запись остаётся без изменений.
- [x] После подтверждения студент исчезает из списка, счётчик уменьшается, показывается «Студент удалён».

**Тест-кейсы:** TC-10.

## US-05. Создание занятия

**История.** Как преподаватель, я хочу создать занятие с группой, датой и дисциплиной,
чтобы привязать отметки посещаемости к конкретной паре.

**Приоритет:** Must. **Спринт:** 3. **Статус:** ⬜ запланировано.

**Критерии приёмки:**

- [ ] На экране «Отметить посещаемость» можно выбрать группу, дату и ввести дисциплину/тему.
- [ ] Дата по умолчанию — текущая; можно выбрать другую дату.
- [ ] Пустая дисциплина не допускается.
- [ ] После создания занятия в списке отображаются студенты выбранной группы.
- [ ] Если в группе нет студентов, выводится сообщение «В группе нет студентов» и занятие не создаётся.

**Тест-кейсы:** TC-11, TC-12 (спринт 3).

## US-06. Отметка статуса посещаемости

**История.** Как преподаватель, я хочу отметить присутствие, отсутствие или опоздание каждого студента,
чтобы точно зафиксировать посещаемость занятия.

**Приоритет:** Must. **Спринт:** 3. **Статус:** ⬜ запланировано.

**Критерии приёмки:**

- [ ] Для каждого студента доступны три статуса: «Присутствовал», «Отсутствовал», «Опоздал».
- [ ] Выбранный статус визуально выделен, остальные статусы снимаются (один выбор на студента).
- [ ] Кнопка «Сохранить» сохраняет отметки всех студентов и показывает подтверждение.
- [ ] Для одного студента на одном занятии сохраняется ровно одна отметка.
- [ ] Без выбранного статуса сохранение невозможно: выводится сообщение «Отметьте всех студентов».

**Тест-кейсы:** TC-13, TC-14 (спринт 3).

---

## US-07. Изменение статуса до сохранения

**История.** Как преподаватель, я хочу исправить статус студента до сохранения занятия,
чтобы ошибка в отметке не попала в статистику.

**Приоритет:** Should. **Спринт:** 3. **Статус:** ⬜ запланировано.

**Критерии приёмки:**

- [ ] До нажатия «Сохранить» статус можно менять любое количество раз.
- [ ] На экране всегда выделен только последний выбранный статус.
- [ ] После сохранения повторное открытие занятия показывает сохранённые статусы.

**Тест-кейсы:** TC-15 (спринт 3).

---

## US-08. Просмотр истории посещаемости

**История.** Как преподаватель, я хочу видеть историю отметок по студенту и группе,
чтобы разобраться в пропусках за прошлые занятия.

**Приоритет:** Should. **Спринт:** 5. **Статус:** ⬜ запланировано.

**Критерии приёмки:**

- [ ] Экран «Статистика» показывает список отметок: дата, дисциплина, статус.
- [ ] Список можно отфильтровать по студенту и группе.
- [ ] Отметки отсортированы по дате (сначала новые).
- [ ] Если отметок нет, выводится «Отметок пока нет».

**Тест-кейсы:** TC-16 (спринт 5).

---

## US-09. Статистика посещаемости

**История.** Как преподаватель, я хочу видеть количество занятий, присутствий, пропусков и опозданий,
чтобы быстро оценить посещаемость студента без ручного подсчёта.

**Приоритет:** Must. **Спринт:** 5. **Статус:** ⬜ запланировано.

**Критерии приёмки:**

- [ ] Для выбранного студента отображаются: всего занятий, присутствий, пропусков, опозданий.
- [ ] Сумма присутствий, пропусков и опозданий равна общему числу занятий.
- [ ] Значения пересчитываются после изменения данных.
- [ ] При отсутствии отметок все показатели равны 0 и выводится пояснение.

**Тест-кейсы:** TC-17 (спринт 5).

---

## US-10. Сохранение данных между запусками

**История.** Как преподаватель, я хочу, чтобы студенты, занятия и отметки сохранялись после закрытия приложения,
чтобы не вводить данные заново каждый день.

**Приоритет:** Must. **Спринт:** 4. **Статус:** ⬜ запланировано.

**Критерии приёмки:**

- [ ] После добавления студента и перезапуска приложения студент остаётся в списке.
- [ ] Отметки посещаемости после перезапуска отображаются на экране занятия.
- [ ] Удалённые записи не появляются снова.
- [ ] Первый запуск на пустой базе не приводит к ошибке: показываются пустые состояния.

**Тест-кейсы:** TC-18 (спринт 4).
