# Спецификация занятия и отметки посещаемости

**Проект:** «Система контроля посещаемости студентов»
**Спринт:** 3 (День 3) — «Занятия и отметка посещаемости»
**Автор:** Product Owner — Чепурнов Дмитрий
**Дата:** 18.11.2026
**Основание:** US-05, US-06, US-07

Документ фиксирует, как преподаватель создаёт занятие и отмечает студентов,
какие статусы используются, как ведёт себя повторная отметка и что видит пользователь
при пустых данных. По нему Lead Developer реализует экраны, а QA составляет тест-кейсы.

## 1. Сценарий занятия

1. Преподаватель открывает раздел «Отметить посещаемость».
2. Выбирает группу из списка (список строится по группам уже добавленных студентов).
3. Проверяет или меняет дату занятия (по умолчанию — сегодня).
4. Вводит дисциплину или тему занятия.
5. Нажимает «Перейти к отметке» — открывается список студентов выбранной группы.
6. Для каждого студента выбирает статус.
7. Нажимает «Сохранить отметки».

Занятие определяется тройкой **группа + дата + дисциплина**. Отдельного списка занятий
в спринте 3 нет: чтобы вернуться к отметкам, преподаватель повторно вводит те же группа/дата/дисциплина.

## 2. Поля экрана занятия

| Поле | Обязательное | Правила | Сообщение об ошибке |
|---|---|---|---|
| Группа | да | выбирается из списка групп, введённых вручную нельзя | «Выберите группу из списка» |
| Дата | да | по умолчанию текущая, можно изменить в календаре | — |
| Дисциплина/тема | да | после `trim()` не пустая, не более 40 символов | «Заполните поле» |

Если в приложении ещё нет студентов, поле группы недоступно, а под кнопкой показывается
сообщение «Сначала добавьте студентов в раздел «Студенты» — без них занятие не создать.»

## 3. Статусы посещаемости

| Статус | Значение |
|---|---|
| **Присутствовал** | студент был на занятии |
| **Отсутствовал** | студента не было |
| **Опоздал** | студент пришёл, но с опозданием |

Правила:

- на одно занятие у студента — **ровно одна** итоговая отметка;
- повторное сохранение того же занятия **заменяет** прежние статусы, а не добавляет новые;
- до нажатия «Сохранить отметки» статус можно менять сколько угодно раз;
- сохраняются только отмеченные студенты: если хотя бы один не выбран,
  сохранение не выполняется и показывается «Отметьте всех студентов»;
- статусы хранятся в памяти приложения до подключения Room (спринт 4).

## 4. Экран отметки посещаемости

- Заголовок: «Отметка посещаемости».
- Подзаголовок: «<Группа> · <Дата> · <Дисциплина>», например «2ИП-4-25 · 18.11.2026 · Информатика».
- Список студентов группы в алфавитном порядке; у каждого — имя и три переключателя статуса.
- Если в группе нет студентов, вместо списка показывается «В группе нет студентов»
  и подсказка добавить студентов; кнопка сохранения недоступна.
- После успешного сохранения показывается сообщение «Отметки сохранены».

## 5. Сообщения

| Ситуация | Текст |
|---|---|
| Группа не выбрана | «Выберите группу из списка» |
| Дисциплина не заполнена | «Заполните поле» |
| Нет студентов в приложении | «Сначала добавьте студентов в раздел «Студенты» — без них занятие не создать.» |
| Не выбран статус хотя бы у одного студента | «Отметьте всех студентов» |
| Нет студентов в группе | «В группе нет студентов» |
| Отметки сохранены | «Отметки сохранены» |

## 6. Правила отображения

- карточка студента: имя, под ним три статуса в столбик (крупные зоны нажатия);
- в списке видны только студенты выбранной группы;
- уже сохранённые статусы подставляются при повторном открытии занятия;
- изменение статуса до сохранения не влияет на другие занятия.

## 7. Ограничения спринта

- занятие не сохраняется отдельной сущностью: список занятий и редактирование даты после
  сохранения появятся вместе с Room;
- отметки живут в памяти и исчезают после полного закрытия приложения;
- статистика по отметкам — спринт 5;
- удаление занятия не предусмотрено.
